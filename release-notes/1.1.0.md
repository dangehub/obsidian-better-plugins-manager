# Better Plugins Manager 1.1.0

## 插件信息 Markdown / Bases 导出

本版本新增了插件信息导出功能，可将已安装插件的元数据（名称、版本、描述、仓库、启用状态、标签等）以 Markdown 文件形式导出到 vault 指定目录。支持两种同步模式：

- **仅导出（export-only）**：单向写入，Obsidian Bases（属性面板）可读取展示，适合作为插件目录清单。
- **双向同步（two-way）**：编辑导出的 Markdown 文件可反向同步到 BPM 设置。当前写回范围限定为插件的 **描述（desc）、备注（note）、分组（group）、标签（tags）和仓库（repo）** 元数据字段。此授权不包含插件启停状态写回——启用状态变更需要下方「启用状态写回」一节的独立授权。

导出使用 `bpm_ro_id` / `bpm_ro_*` 只读属性与 `bpm_rw_*` 可写属性分离的 YAML 方案，支持自定义属性保留、冲突检测与写保护。

### 启用状态写回（需额外授权）

通过 Markdown 文件修改插件启用状态（`bpm_rw_enabled`）是一项高风险操作，默认关闭。用户必须在 BPM 设置中开启 **"允许通过导出笔记控制启用状态"** 选项（`PLUGIN_NOTES_ALLOW_ENABLED_WRITE`）后方可生效。即使开启该选项，BPM 也会保护自身免于被停用：如果尝试将 `better-plugins-manager` 的 `bpm_rw_enabled` 设为 `false`，BPM 会忽略该请求并维持启用状态。

## 共享 RepoResolver 数据链

导出流程与安装来源管理共享仓库解析数据链。`RepoResolver` 提供批量 resolve、本地 REPO_MAP 缓存→社区列表→网络请求的分级策略，单次批量请求最多一次网络调用和一次保存，避免重复写入。exportAll/exportSingle 在写入前调用 resolveRepos，确保导出文件包含仓库来源信息。

## 迁移与路径 / YAML 安全

- 自动迁移旧版 `EXPORT_DIR` 设置为新的 `PLUGIN_NOTES_EXPORT_DIR`，版本锁定防止预执行未来迁移。
- 导出路径严格校验：拒绝绝对路径、路径遍历（`..`）、`.obsidian` 系统目录。
- YAML 解析/序列化使用严格布尔值检查（`bpm_rw_enabled` 要求字面量 `true`/`false` 而非字符串 `"false"`），避免误写。

## 测试覆盖

测试套件覆盖以下领域，共 75 个测试用例（主模块 51 + 解析器 24），经过自动测试（含集成覆盖）与测试 Vault 实际环境验收：

- 类型编解码、严格布尔值、路径校验
- 导出器：目录索引、增量写入、无变更跳过、冲突处理、写入失败回滚
- SyncService：串行队列、按路径去抖、自写入 Token 抑制、停止守卫、TTL 过期
- 写回：字符串 `"false"` 不触发、严格布尔值正确调用 API、BPM 自身跳过、API 失败回滚、类型混合标签丢弃
- PluginNotesService：空目录启动拒绝、无效路径拒绝
- RepoResolver：缓存层、社区列表解析、批量请求合并、不覆盖已有映射、网络失败处理
